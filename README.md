# Subsea Layout Designer

Streamlit shell + JavaScript/SVG designer, with an optional locally bundled Three.js underwater viewer.

    pip install -r requirements.txt
    streamlit run app.py

- Host, equipment and line symbols, including riser bases and riser connection skids. Auto tags (HV-101), line numbers, ISA instrument bubbles, ISO flanges.
- Four themes: Consulting navy (slide layout with action title, rule, source footer), Engineering mono, Blueprint, Classic (sheet layout: frame, grid references, title block, notes).
- Each new session starts with **Blank canvas – draw your own**, with no host or equipment. Templates and saved designs load only when explicitly requested. The viewer's compact **Symbols** drawer is available for every layout: add equipment to a preset's main flowpath, or drag symbols to a chosen position. On the blank canvas, place symbols freely on the grid. Use **Full screen** for detailed editing.
- **Installation tags & costing export:** in **Review design > Equipment list**, tag equipment, hosts, preset risers and drawn connections as **New**, **Existing** or **Unspecified**, with **Provider**, **Installation type**, **Rating** (including units, e.g. `10 K psi`) and optional actual **Installed length (km)**. Apply the table before exporting. Tags are also editable in the drawing inspector and Selected item settings, and persist in JSON/case versions. Newly placed/copied objects default to New; untagged imported/template objects remain Unspecified, excluded from costing until classified.
- Download **new installation Excel** (exact item list, grouped quantities and notes) or **PDF** (grouped quantities and every new item's details). Existing/Unspecified items are excluded; missing provider/type/rating and unclassified items are flagged in the export notes. Quantities count explicitly listed drawing objects, not internal template wells, hubs or implicit piping. Hosts and preset risers are included. Each connector counts as one segment; do not represent the same installed segment both as a flowline symbol and a connector. Lengths are entered engineering values (or a flowline symbol's `pKm`), never schematic measurements; unknown lengths remain blank and are counted in the summary. The list is a drawing inventory, not an automatically inferred procurement breakdown.
- **New blank design** in the sidebar starts an empty drawing in one click, with no host or equipment. Save a case version or download JSON first if you want to keep the current design.
- Six **North Sea concept** presets provide editable examples of subsea separation/boosting, daisy-chain templates, oil with independent water injection, a heated tieback with MEG/electrical supply, gas compression and brownfield satellite tie-ins. These are generic illustrative architecture patterns, not verified or operator-specific as-built configurations.
- Use **Connect** to reveal green circular connection ports, then drag from one port to a matching-lane port on another symbol. Connectors attach to the line endpoints and stay attached when symbols move. Select a symbol to copy or delete it; select a connector to delete it. The Delete/Backspace keys work for the current selection. Connectors are included in JSON/SVG/PNG exports.
- **Edit connection routes:** leave Connect mode, select a connection, then drag its line to move the interior route without detaching its ends. Use **Add bend**, drag a blue bend handle, or double-click the line to add a bend (double-click a bend to remove it). Drag an end handle onto another matching port to reconnect it. **Auto route** removes manual bends and restores automatic routing. Clicking a preset host riser converts that riser into an editable, port-attached connection; other preset risers remain unchanged.
- **Flow and thickness:** drawn connections now have moving flow dashes and direction arrows as well as preset flowlines. Use **Flow** / the speed slider or the sidebar animation controls; set forward/reverse/none per connection in its inspector or settings below. Automatic follows the layout/train direction. **Default connection thickness** in the sidebar controls unconfigured flowline connectors and flowline symbols, not risers. Select a connector/riser to override its own thickness (or **Use default thickness**), or select a flowline symbol and change **Flowline thickness**. Thickness is in drawing units (0.5-20), independent of viewport zoom. Editing a flowline's thickness does not change riser width or bend geometry; selecting an older preset riser retains its sweep bend when converting it to an editable connection.
- **Move a block:** Shift-click (or Ctrl/Cmd-click) symbols to add/remove them from a multiple selection, then drag any selected symbol. Unselected symbols stay put; connected ends follow, and manual bends translate with the block when both ends are selected. Click the background to clear the selection. Delete removes the selected block and its attached connections.
- **Fit view** only adjusts zoom. **Best layout** spaces disconnected freeform blocks in rows, keeping connected equipment and every manual pipe bend together as a rigid block. Route extents and anchored zones are included in spacing; custom internals, scales and labels are unchanged. It does not separate overlapping equipment inside a connected network or redraw engineered routes. A single connected block, freely positioned zones or freeform preset/implicit paths keep the existing composition: only the view is fitted, with an explanatory status. Hidden/missing connection endpoints must be revealed/reconnected before automatic spacing. For preset drawings it spaces complete train blocks, preserving inline piping rather than separating equipment from its implicit connections. It is a schematic spacing aid, not an engineering routing optimizer. **Undo layout** restores the previous design until the next design edit; repeated unchanged layout clicks retain that undo.
- **Improve appearance** is a presentation-only alternative to Best layout: it uses a consistent sans-serif caption hierarchy, clearer label contrast, lighter engineering hatching and small secondary equipment tags above captions. Automatic captions/tags remain readable on smaller symbols; explicitly configured label sizes are retained. It adds unique missing tags across the whole drawing, preserving existing tags (including deliberately blank tags) and respecting disabled automatic tagging. Generated prefixes/numbers are illustrative drawing identifiers, not an engineering tag-standard certification; edit tags in element properties as needed. Custom font sizes/styles, label offsets/rotation, label text, themes and service colours are retained. Equipment positions/sizes, ports, internal piping, connection paths/bends and zoom do not change. It does not automatically resolve crowded labels; use per-element label placement for those. **Undo appearance** restores the complete previous appearance until another design edit; repeated Improve clicks do not renumber tags, but can fill missing tags after adding/copying equipment. The appearance and tags persist in cases and JSON/SVG/PNG exports. Use Fit view separately if larger annotations extend beyond the current viewport.
- **Sea level:** expand **Sea level** in the sidebar, enable **Show sea level**, choose its host and set **Sea-level offset**. Zero aligns the line to the top of the selected host; positive offsets move down and negative offsets move up, in drawing units. The line follows host movement/resizing and appears in drawing exports. This is separate from the seabed line and title rule.
- Click an element, then open **Edit design > Selected item**: edit its label, size, offsets, wells or J-tube names, and additional JSON properties. Valid edits update automatically when you leave a field or finish a table cell, with no Apply button. Drawing-inspector equipment, port and valve edits work the same way. Invalid drafts show an error and leave the last valid design unchanged. Selecting an item does not modify it. Bulk-edit tables elsewhere still require their labelled Apply button. Viewer edits synchronize to Streamlit session state automatically; zoom and selection are preserved. Save a case version or download JSON for a durable backup; loading a template intentionally starts over.
- **Label font and placement:** select equipment, a host, a flowline symbol or a connection, then expand this section in its drawing inspector or settings below. Choose theme/sans-serif/serif/monospace font, size, normal/bold weight, italic, alignment, horizontal/vertical offsets and additional rotation. Both editors update automatically. Size **0** and **Symbol default** retain the original typography; **Reset label style** restores the original placement/font. Offsets affect labels only, not ports or piping, and are in local symbol coordinates (right/down; mirrored trains mirror the horizontal direction). Fonts scale with equipment. Formatting applies to primary equipment/host captions and flowline service descriptions, not port IDs, well numbers or internal instrument markings. Add label text to hosts/instruments without an existing caption. Styles are retained when copying, saving cases or exporting JSON/SVG/PNG.
- **Edit design > All equipment** is an editable inventory of all trains, hosts (including independently placed hosts), equipment and flowline symbols. Edit labels, size, offsets, hidden state or properties JSON (positions, ports, J-tubes, design limits), then **Apply all equipment settings**. IDs/types are protected, occupied ports cannot be removed, and unchanged geometry and connections are retained. The table follows drawing edits; hidden items remain listed so they can be shown again.
- **Workspace organization:** the canvas stays above four work areas. **Edit design** contains Selected item, Equipment chain, Host & risers, Network, Zones, All equipment, Add equipment and Design specification. **Review design** contains Design checks, Equipment list and Compare designs. **Save & export** contains Saved cases and Spec JSON (including standalone HTML export). **Symbol reference** is the searchable catalogue. The sidebar groups document setup, appearance, titles, view/animation and sea-level settings; expand only what you need. Pick a preset, then explicitly **Load template** to replace the drawing; choosing a template name alone is safe. Save your current work before loading a template, importing JSON or starting blank. Imported designs are not associated with the previous saved case.
- **Drawing toolbar:** commands are grouped into Draw, View, Arrange, Presentation, Flow and Export, with a separate status/help strip. **Fit view** changes zoom only; **Best layout** moves equipment; **Improve appearance** changes presentation without moving equipment. **Reset overrides** clears manual position, size, label and visibility overrides (the old "Reset moves" label understated this scope). Toggle buttons expose their actual state, and all groups wrap on narrower screens. Colours and drawing themes are unchanged.
- **3D view / 2D design:** switch using the drawing toolbar. The optional JavaScript 3D scene has dark-gray, illustrative bathymetry-style terrain with channels and slopes, without contour or grid overlays, plus sediment, underwater lighting and shadows. Equipment pads and piping corridors remain locally level to preserve connections; terrain is procedurally generated, not measured bathymetry. Procedural equipment families cover the complete catalogue: jackets/topside units, trees/templates/manifolds, skids, bolted hubs, actuator/handwheel valves, pumps, vessels, controls, protection and pipelines. Equipment uses consistent yellow housings, frames and protective covers where appropriate; machined fittings, service-colored pipes/cables and gray platform topsides remain recognizable. PLEMs retain their low yellow skid and white process bore; custom drawing colors and closed-valve red indicators are retained. Actual rendered 2D piping, hub/valve locations, custom-element shapes and zone positions feed the scene; riser PSVs remain at their illustrative topside termination. Provider, rating and installation data remain in the same design/inspector. These are **procedural concept models, NOT TO SCALE**, not manufacturer CAD, surveyed bathymetry, collision/clearance analysis or FieldTwin-level engineering/digital-twin fidelity. Custom rectangles/circles are illustrative solids; custom lines are decorative, not inferred pipes. Internal model parts do not add costing quantities.
- **Quiet defaults:** 3D equipment labels and flow animation start off. Use **Labels** and **Animate flow** to enable them. Saved designs retain an explicit animation choice, and exported 3D HTML retains the chosen label visibility.
- **Per-element 3D size:** select an element and set **3D size (%)** in its inspector, or use **3D smaller**, **3D larger** and **Reset 3D size**. For example, 50% halves its width, depth and height; 150% enlarges it. Sizes start at 100%, with a 1% minimum. This is separate from the existing base component size: it does not change the 2D drawing, equipment quantities or costing data. Ports and attached flowlines/risers follow the resized model. The choice is retained in JSON, saved cases and offline 3D HTML; SVG/PNG reflect the current size. Models remain illustrative, not dimensionally qualified.
- **Manifold service/control attachments:** production, service and umbilical headers have matching P/S/U ports, like templates. Existing inline service and control lines follow manifold movement and resizing instead of leaving duplicate stationary bypass lines behind. This also applies when loading older designs; no equipment or costing quantities are added.
- **FPSO and jackup concepts:** the FPSO has a shaped red hull, gray process modules and pipe racks, accommodation/bridge glazing, crane, helideck and turret-connected risers with illustrative moorings. The 2D FPSO is also ship-shaped (monochrome/blueprint exports retain their theme). A separate **Jackup drilling / well-test unit** host has three lattice legs, spudcans, elevated deck and a cantilevered derrick. Choose **Single 4-slot template to jackup**, then **Load template** for one four-well template, SSIV, SDU, flowline and separate production/service/control risers. Save current work first: loading replaces the drawing. Sizes, lengths, ratings and the jackup's receiving duty require project engineering; this preset is not a qualified production facility. Decorative vessel/leg parts do not add costing items.
- In 3D, drag to **Orbit / inspect**, right-drag to pan, use the wheel or existing zoom buttons, **Top view**, **Labels**, and **Fit view**. Click equipment to use the existing inspector. **Move equipment** drags it on a horizontal seabed plane; attached flowlines and risers follow during dragging and after release, including host/J-tube/PSV attachments. Release to save offsets, or press Escape to restore the equipment and its attached routes. Adjacent inline schematic equipment retains its existing matching pipe attachments when separated; these derived 3D links do not add equipment/costing quantities or saved connection records. Freeform proximity alone does not create connections. Movement synchronizes with 2D and Streamlit; JSON and explicitly saved case versions retain it. Camera, mode and rendering objects are transient in saved cases. Add equipment, edit custom internals and arrange the design in 2D. **Animate flow** and its speed slider control illustrative 3D pulses with forward/reverse/none per connector; they are not a flow simulation. PNG exports the active view; print remains 2D-only.
- **Drag-connect and flexible routing in 3D:** choose **Connect / route lines**, optionally **Top view**, and zoom in. Drag a round handle at a flowline/equipment end onto another element's matching port: purple **P** production, orange **S** service, gray **U** umbilical; white named host ports accept any lane. The target turns green when ready to connect. Hover a handle for its element/port name. Release to save a flexible connecting segment across the gap; this does not change the existing equipment's physical type or certify a rigid pipeline as flexible. Drag a square handle (or the body of a saved line with no bends) to reshape its horizontal route. Select a saved line to expose its two draggable endpoints, then drop an endpoint onto another matching port to reconnect it. Existing bends and other connection metadata are retained. Escape, an interrupted drag or an incompatible/empty drop leaves the original design unchanged; duplicate connections are rejected. Close ports require zooming in. New connecting segments are explicit **New** installation records, visible in the ordinary connection inspector and installation inventory; supply actual lengths, provider/type/rating and engineering data there. Port attachments follow equipment movement and independent 3D scaling. Edits synchronize with 2D/Streamlit and persist in JSON, explicitly saved cases and exported HTML. Round/square editing handles are excluded from SVG/PNG exports. Preset/derived links keep their original installation records; use **Anchor points** to edit their routing without creating extra connectors.
- **3D anchor editor:** choose **Anchor points**, then click a line or select it in **Flowline / service / umbilical**. This includes saved connectors, pipeline/spool/jumper/cable symbols (each P/S/U bore separately), preset risers and implicit/derived links. **Add anchor** inserts after the selected point; click or drag a green ring to insert between its two neighbours. Drag square anchors horizontally, or select an anchor and edit **Layout X**, **Layout Y** and **Height (3D units)** for precise positioning. **Remove anchor** deletes only the selected point; Delete/Backspace does the same when the 3D canvas has focus. Removing the last anchor restores the line's default route. Escape or an interrupted drag restores the previous route. Endpoints remain attached when equipment moves/resizes; manually placed anchors stay at their chosen layout positions/heights. Saved connectors share their plan-view bends with 2D; pipeline/preset/derived-line overrides are 3D-only and stored in `routeAnchors3D`. JSON, saved cases and offline HTML retain the edits. No equipment, connections or installation quantities are added by anchor editing. Coordinates/heights are illustrative, not metres or validated engineering geometry.
- **3D exports:** use **3D HTML** in the drawing toolbar to download an offline, self-contained viewer containing the current design, camera and label visibility. Open that HTML in a modern browser to orbit, pan, zoom, animate flow or inspect equipment without Streamlit or internet access. Further edits can be preserved by exporting HTML/JSON again. **SVG** in 3D exports a true vector, flat projection from the current camera, not an embedded PNG: zoom it in a browser or vector editor. It cannot rotate in 3D; use HTML for that. The SVG contains terrain/equipment meshes, piping and visible labels with simplified lighting, without texture maps, shadows or animated particles. SVG in 2D retains the existing engineering drawing export. Exports include your design and installation metadata; share them only with intended recipients.
- 3D requires a modern browser with **WebGL2** and **DecompressionStream**. Three.js **0.187.0** is pinned in `subsea/static/vendor/package.json`; its official browser builds and MIT license are vendored locally and gzip-embedded in standalone HTML, loaded only on request. No runtime CDN/network access is needed. Graphics/loading failures are shown explicitly; **2D design** remains available. Reload the viewer after graphics-context loss, saving unsaved work first.
- **3D close inspection and reference-style equipment:** use **Focus selected** after clicking equipment, then zoom with the wheel (toward the cursor) or +/- buttons. Close/far zoom is no longer constrained to the old 2/20,000 scene-unit range; camera clipping and haze adapt to zoom. The dark-gray seabed has no contour/grid overlays and is not imported/surveyed bathymetry. Templates, PLETs and other protected equipment have yellow hoods, roof panels, sloping gussets and mudmats. Fixed platforms have yellow tapered jackets with connected bracing, gray topside modules, process equipment/towers, guardrails and lattice cranes. PLEMs have low yellow skids/clamps and a swept white process bore, with their actual hub and valve locations following that bore. Physical pipes and custom hub stubs remain visible when flow is set to None; disabling animation does not remove connections. Inline schematic trains share a pipe elevation so adjacent symbols meet; freeform external flowlines follow their locally level corridors with short port transitions. Implicit drawn lines retain their endpoint identities when equipment moves rather than snapping to unrelated nearby ports.
- **3D host risers/J-tubes:** deck slots are positioned relative to the actual procedural host, not projected 2D elevation offsets. Visible J-tubes have curved seabed mouths, semi-transparent walls, flanges and leg support brackets, sharing their path with the colored pulled-in riser. Fixed-jacket/platform and jackup risers follow the host guide down the structure and sweep into the seabed route, including flexible lines; hiding the J-tube wall does not turn these into free-hanging arcs. Unconfined flexible risers at floating hosts retain catenary/lazy-wave/S profiles; FPSO hang-offs meet the modeled turret. Manual riser waypoints control the seabed route; when present, or when pulled into visible J-tubes, the host-side guide controls the vertical section. Reversing endpoints preserves the physical route, and PSVs sit at the corresponding 3D termination. All of this is illustrative and changes only the 3D representation; saved routing and costing metadata are retained.
- **Batch editing train tables:** Equipment chain and Host & risers tables now stage cell changes without rerunning/redrawing on every edit. Make multiple edits, then **Apply equipment chain** / **Apply risers** to commit them together; **Discard edits** resets the unapplied draft. Zones and the all-equipment inventory also provide Apply, Discard and Undo. Invalid changes are rejected without partially updating the drawing. **Undo** restores the last applied table transaction (one level, across tables) and is disabled after another design edit or document load, so newer work is not overwritten. Apply drafts before switching trains, changing the drawing or loading another design; these actions can reset unapplied edits. Reorder/remove buttons and non-table train controls still act immediately.
- **Actual design hosts:** **Host & risers > Design host** lists the preset source and all independently placed hosts in the editing train. Selecting a host in the drawing updates these settings too. Slot names and host type edit that actual host, including on blank or loaded designs. **Drawn host connections / risers** lists its attached connections; edit their labels, physical kind, shape, service or host port, then **Apply host connections**, **Discard host connection edits** or **Undo host connections**. `J-0` means the first named J-tube. Existing bends, opposite endpoints and other connection properties are retained. The separate preset-riser table appears only for the train source; enabling a preset source is optional and does not replace library hosts.
- **Zones:** click **+ Zone** in the drawing toolbar. Select equipment first to anchor the zone to it, or leave equipment unselected to place it anywhere. Click its arrow, dashed boundary or label to open the automatic editor. Drag the blue left/right handles independently, the centre handle to change arrow height, the bottom handle to change dashed-line depth, or the label to position text. Numeric drawing coordinates provide precise adjustment; these are not metres. Use multiple independent annotations for LC1, LC2 and Fortified zone, with separate arrowheads, dashed edges and heights. Switch between free placement and following equipment without losing the visible position. Anchored adjustments follow equipment movement/resizing. The Zones tab retains an **Advanced: zone table** with Apply/Discard/Undo for bulk edits; it preserves drawing adjustments. Save a case version for durable storage. Geometry and labels survive JSON, saved cases and SVG/PNG exports; editing handles are excluded from image exports.
- **Saved cases**: enter a case name and version note, then **Save case version**. The first save creates a case; subsequent saves create new numbered snapshots without overwriting earlier versions. **Save as a new case** creates an independent case from the working drawing. Select any saved case/version to **Load saved version**, **Duplicate saved case**, or delete a single version/the entire case with explicit confirmation. Loading replaces the working drawing; save unsaved work first. Deleting saved data does not delete the working drawing. Saving is explicit, not automatic.
- Cases persist across app restarts in a local SQLite file at `%LOCALAPPDATA%\SubseaLayoutDesigner\cases.sqlite3` on Windows (or `~/SubseaLayoutDesigner/cases.sqlite3` without `LOCALAPPDATA`). The actual location is shown in **Saved cases**. Set `SUBSEA_CASES_PATH` to an alternative database file before starting the app. Storage uses transactions and unique case IDs; version numbering is not reused after deleting a version. Use JSON downloads for portable, per-design backups. In a remotely hosted deployment, "local" means the server running Streamlit, not the browser computer.
- **Compare designs**: choose any two saved versions, or compare a saved version with **Current drawing**, then click **Compare designs**. Two drawing previews appear side by side, with added/removed equipment/connections and field-level differences for geometry, ports, engineering metadata, ordering and settings. Download differences as CSV. Equipment is matched by ID and connections by endpoint ports; independently renamed IDs appear as removed/added items. Comparisons are snapshots: click Compare again after editing. Preview edits are temporary and never update saved cases or the working drawing.
- Viewer: pan, zoom, hover info, click to rename, drag to move; export SVG / PNG / JSON.
- Select a component to resize it using **Smaller**, **Larger**, or **Component size (%)** in the inspector; **100%** restores its original size. This changes only that symbol, not the canvas zoom or neighbouring symbols. Connection ports resize with the component, and its size is retained when copied or exported.
- **Symbols > Hosts & topsides** includes ten host types: jacket, small platform, FPSO, semi-submersible, TLP, spar, wind/power hub, hybrid riser tower, onshore terminal, and existing infrastructure tie-in. Click a host and then click the canvas, or drag it onto the drawing; multiple hosts can be placed independently without replacing the main host. Existing preset hosts are also selectable: move, resize, relabel, copy, or delete them. Main-host risers stay attached when it moves or resizes; use green connection ports for connections to additional hosts.
- **Available J-tubes:** select a host and set its count (0-24) in the inspector or selected settings below. Existing names are retained; new slots receive J1/J2/... names. The jacket deck expands to fit its labels. Set custom names with **J-tube labels**. A J-tube with an attached riser cannot be removed until that riser is reassigned/deleted. Hosts with no J-tubes expose no J-tube handles.
- **Visible J-tube guides:** select a fixed jacket/platform host and enable **Draw J-tubes with pulled-in risers**, then apply. Slender parallel tubes descend inside the jacket from the deck and sweep outward near the seabed, without external overhead elbows. **J-tube seabed exit** selects left (default) or right. Connect a riser to that mouth's J handle: its service colour continues inside the tube up to the deck. Existing explicit and preset risers follow the moved mouths; labels, scaling, saved designs and SVG exports retain the option. Disable it to return to the original slot view without removing lines. This is illustrative, not a tube-clearance or bend-radius check. Test: `python tests\test_jtube_guides.py`.
- **Assign a riser to a J-tube:** click **Connect**, then drag an equipment port onto a labelled green J-tube point on a host (or drag in the opposite direction). Select the resulting riser to choose **Rigid** or **Flexible**, or change **Host J-tube**. Each host slot has its own point, using its configured name (J1/J2 by default). Riser connections follow moved/resized hosts and equipment and are retained in JSON/SVG/PNG exports. Onshore and existing-infrastructure hosts have ordinary tie-in ports rather than J-tubes.
- **Explicit riser classification and shapes:** select any drawn connection, including one between subsea elements, and set **Physical connection > Riser** in the inspector or connection settings below the drawing. Choose **Riser shape**: rigid swept bend, flexible catenary, flexible lazy wave, or flexible S shape. Choosing a shape directly in the drawing inspector also marks the line as a riser. This physical classification is separate from the oil/gas/water/umbilical service type. Manual route points are retained: rigid risers round their corners and flexible risers follow a smooth curve through their points. With manual points present, those points define the route; **Auto route** clears them and restores the selected automatic profile. Fluid, theme, label and thickness edits do not reset bends. Reconnecting to non-host equipment also retains an explicitly chosen riser classification and shape. Shapes are illustrative schematics, not calculated installation profiles or bend-radius checks.
- **Riser PSV:** enable **Add PSV to riser** in the connection inspector or Selected item settings and enter its tag. The compact PSV symbol is fixed at the **topside riser termination**, regardless of drawing direction or an older saved percentage. It is drawn above platform geometry so the deck and structure cannot hide it. When J-tubes are shown, it sits at their deck-level termination, not at the seabed tube mouth. Preset risers provide **Add PSV** and **PSV tag** in Host & risers. Their legacy position column is read-only. **PSV position (%)** only controls risers between equipment with no topside host (measured from the From endpoint); Network preserves this field for compatibility. The marker follows host movement, sizing and route changes, survives case/JSON reloads and SVG/PNG exports, and remains at the topside when converting a preset riser to a drawn connection. This is a schematic valve annotation, not relief sizing or verification. It is not a separate procurement item in the costing inventory.
- **Current design network:** Network automatically lists all equipment/hosts, explicit port-to-port connections, preset risers, inline train paths and branch tie-ins/rejoins. Edit drawn connections' physical kind, service, shape, label and PSV fields, then **Apply network connections**. Endpoints are protected; reconnect them on the canvas. Apply, Discard and Undo preserve geometry, bends and installation metadata. Preset/implicit paths are shown separately, without creating duplicate connections; edit them through Host & risers or the existing train controls.
- **Distance zones:** enter an optional positive engineering distance and choose **metres** or **kilometres** in the drawing's zone editor. Values are stored in metres; switching units preserves the distance. An anchored distance begins at the selected symbol's edge in the chosen left/right direction; the end item is ignored and **start at host** is off. Its initial schematic span can be adjusted independently using the boundary handles. Free zones can display distances too. Labels show **NOT TO SCALE**: moving a boundary does not change the engineering distance, and entered distances do not reposition equipment. Leave distance blank for a named zone without a distance.
- **PLET connections:** process, service and umbilical lanes are enclosed in the same PLET frame, above its support base. S/U ports no longer appear as detached fittings below the equipment. Port IDs, lane elevations and existing connections are unchanged; custom fluid labels remain visible.
- **Single-pair PLET:** select a PLET and choose **PLET standard ports > Process only (1 inlet + 1 outlet)** in the inspector or settings below, then apply. Disable custom hubs for exactly one pair. This removes S/U lanes and shrinks the frame; connected S/U ports must first be disconnected/reassigned. The existing three-pair configuration remains available and is retained for older designs. Process-port fluid can still be set individually.
- **Service-only / umbilical-only PLET:** under **PLET standard ports**, choose **Service / chemical only** or **Umbilical only**, then apply. Each draws a compact PLET with exactly one standard inlet/outlet pair (S or U), without process piping. Disable custom hubs for exactly two total ports. Use Connect with matching S/U equipment ports; set Chemical/MEG or static/dynamic umbilical per port as needed. Changing modes cannot remove connected ports until their lines are reassigned/deleted. Modes persist in saved designs and exports; older PLETs retain all three standard pairs.
- **Chemical-only PLET:** assign Chemical/MEG injection or Service line to each required PLET port, then apply. The assigned service sets compatibility automatically (S for chemical/service, U for umbilical/power, P for process fluids), including on single-pair PLETs whose physical port IDs start with P. Connect these S-compatible ports to the template's orange S port. PLET compatibility is service-derived in both settings panels, even with older stored Lane values. Previously saved explicit PLET attachments remain visible; validation flags incompatible legacy lines so they can be reconnected rather than silently disappearing.
- **PLET inlet/outlet display:** in **Individual inlet / outlet**, select the inlet (left) or outlet (right) and edit its label and fluid/service; valid edits update automatically. Each half of the PLET piping displays its own service colour and dash pattern; editing the inlet no longer recolours the outlet. Label-only edits are visible too. These independent settings persist through reloads and drawing exports.
- **Jumper / Spool tags:** select a connection and choose **Physical connection > Jumper** or **Spool**, either in the drawing inspector or settings below. These classifications are independent of fluid/service type; they preserve attachment ports and manual route points and are retained in saved cases, JSON and comparisons. They do not automatically generate a new jumper/spool geometry.
- **Adding riser-base hubs:** select the base, choose **Additional hubs** and set inlet/outlet counts; the drawing updates automatically. Changed positive counts automatically enable customization. To remove unused custom hubs, uncheck customization without changing the counts. Connected hubs remain protected. The same behavior applies to other subsea equipment.
- **Internal riser-base/skid connections:** custom inlet/outlet hubs, branch piping and labels are drawn inside the equipment enclosure rather than on external legs. The frame grows downwards with the configured hub count; the skid support follows its bottom edge. Existing port IDs, fluid assignments and attached lines are retained. External connections still attach to the same hubs, with endpoints following their new internal positions.
- **Custom internal valves:** select equipment with internal piping. **Internal valves** opens at the top of its drawing inspector: click **Add internal valve**, then choose its pipe/type/position; valid changes display automatically. Position **0%** is the pipe start, **50%** its middle and **100%** its end; P/S/U mean process/service/umbilical. The inspector starts with the symbol's existing valves. Alternatively, in **Edit design > Selected item**, enable **Customize internal valves (replace defaults)** to reveal the automatically updating table. Complete required fields in a new row before it can be saved. Add/remove valves and edit each unique ID, internal pipe, position, type, tag, label, open/closed state, provider and pressure rating (include units, e.g. `10 K psi`). Types include gate/ball isolation, check, control, PSV, ESDV, SSIV, choke and crossover.
- Customization replaces the complete built-in valve set; an empty custom list deliberately draws no internal valves. **Restore symbol valve defaults** (or untick customization and apply) restores the original valves. Piping, ports, equipment positions, external connections and route bends are retained. Valves stay attached to their selected pipes during movement/resizing; named custom riser routes use `route-<ID>`. After changing equipment topology, review the pipe selection: missing pipes are reported explicitly on the canvas rather than silently moving a valve elsewhere. Internal pipe IDs are discovered from the current drawing when selecting an element; apply piping changes first, then customize valves.
- Internal valve configurations persist in copied elements, saved cases and JSON/SVG/PNG exports. **Internal valves (JSON)** in equipment CSV and costing Excel/PDF includes each valve's metadata under its parent equipment. Internal valves are not counted as separate procurement items. These are schematic annotations and unverified specifications, not a piping safety, relief-sizing, valve capacity or pressure-rating check; open/closed state does not calculate flow or isolation.
- **Riser-base service/umbilical options:** select a riser base or riser skid and enable **Include chemical / service connections** and/or **Include umbilical connections**, then apply options (or element settings below the drawing). Each adds an inlet/outlet pair inside the frame: S for chemical/service and U for umbilical, alongside existing process and custom hubs. Use **Connect** to attach matching ports on templates, PLETs or other equipment. Per-port settings allow specific chemical or static/dynamic umbilical assignments. Options persist in saved designs and exports; occupied pairs cannot be disabled until disconnected. Existing designs remain process-only unless enabled.
- **One bundled S/U riser to a J-tube:** on a riser base/skid, enable **Bundle S inlet into U inlet (one umbilical riser)** and apply. Enable service/umbilical pairs first, or provide U-left and S-right with independent counts. The external S-left handle disappears and its internal chemical path joins a labelled **U + chemical inlet** at U-left. Connect that single U-compatible inlet to the desired host J-tube; use Static/Dynamic umbilical and the required riser shape. S-right and U-right remain separate subsea outlets. Legacy process piping, valves and extra process hubs are unchanged. Existing custom routes referencing S-left use it as an internal junction rather than an external handle; in the internal-route table it remains an available virtual endpoint. An explicit empty internal-route table still means no chemical branch until one is added. Bundling is a schematic representation of chemical service carried within an umbilical, not fluid mixing or a verified J-tube capacity check. If S-left is already connected, disconnect/reassign that line first; the editor will not silently delete it. Uncheck the option to restore the separately configured S inlet. Bundling, internal routes, riser bends and attachments persist in saved designs and exports.
- **Custom FURB / internal riser-base piping:** select a base/skid and click **Load FURB starting layout**. It applies immediately in both settings panels, retaining existing hub counts and external connections while adding any missing FURB ports. This starts with separate gas and umbilical through-lines and a chemical take-off at the umbilical's internal junction. It is an editable schematic starting point, not a reconstruction or engineering verification of a specific installation. **Independent process / service / umbilical hubs** allows separate 0-24 inlet/outlet counts for all three services together; it overrides legacy single-lane counts. With **Custom internal piping (replace default lines)**, edit/add/remove internal routes. Use port IDs for From/To and a unique Route ID for each line. For example, `umb: U-left -> U-right, umbilical_static`, then `chem: @umb -> S-right, chemical` creates a chemical take-off from the umbilical route's internal junction. Junctions can reference direct port-to-port routes only; they do not imply mixing every service inside an umbilical. Delete all routes to leave only hubs and the enclosure, without unwanted continuous pipes, valves or GL branches. Custom hubs have no implicit piping: draw each required route explicitly. In the below-drawing form, enable an option and apply once to reveal its editors. Explicit external connection types take precedence; otherwise unambiguous attached internal routes supply the service colour. Port removal and invalid/dangling routes are blocked; routing and counts persist in saved versions and SVG/JSON exports. Existing designs retain their legacy piping until these options are enabled.

The below-drawing form has equivalent controls beneath the element properties. This adds an internal branch (`@process -> P-out-1`) with the trunk's service/colour while keeping existing routes and the outlet's external connection, such as a pig receiver. Only unrouted internal hubs are offered; external occupancy does not block internal piping. This shortcut requires the same service lane and a direct internal trunk. To reroute an already internally connected hub or create a cross-service take-off, use the internal route editor.

## Network model
A spec is a main train plus optional `branches`. Each branch has its own `fluid`
(production, water, gas, gaslift, export, chemical, co2, power), `lanes`, optional `host`,
and a `from: {item, side, dx, valve, label}` tie-in into any item of another train.
Ids are unique across the whole network. Per-item `lane` overrides the lane of generic symbols.

## Design checks and equipment list
**Review design > Design checks** automatically screens the current design without modifying it.
Results are grouped by discipline, with reference, severity, evidence/limitations and required follow-up:
- **Action required:** data conflicts, missing endpoints, disconnected equipment/groups, repeated port use, service/lane mismatches, declared item limits below layout limits, duplicate explicit tags or incomplete installation/procurement metadata.
- **Not assessed:** missing item-specific data or checks requiring project criteria, datasheets, calculations, surveys or engineering sign-off. Layout defaults and free-text ratings do not prove certified capacity.
- **Screened:** only the stated data comparison or declared-connectivity check completed. This is not a design pass or approval.

Coverage includes design basis, pressure/temperature declarations, network topology, isolation/safety,
hydraulics/flow assurance, materials/mechanical integrity, risers/host interfaces, seabed/protection,
controls/power, operability/maintenance, installation/commissioning and procurement identification.
Train-order heuristics run only for schematic trains; freeform equipment-list order and proximity do not establish piping.
Structure names alone are not proof of isolation; two valves on one side of a pump do not establish isolation on both sides.
The legacy 15 km pigging trigger is a screening heuristic, not a standard requirement.
Connectivity combines declared links of all services and does not prove process continuity or internal valve lineup.
Drawing coordinates, zone-distance labels and procedural 3D terrain are never used as engineering clearances.

Filter by area/status; **Download full concept review (CSV / Excel / PDF)** includes every result regardless of filters.
The Excel workbook has an **Open checklist** for Action required/Not assessed results, **Full review**,
**Coverage**, and **Read me** sheets. Check numbers link open items to the full review.
The paginated PDF contains the full discipline-grouped checklist, status counts, coverage,
references, findings, required follow-up and evidence/limitations. Both include assessment caveats;
Screened results are retained for context, not presented as engineering approval.
No standards/editions or project acceptance criteria are currently specified. This review is advisory,
not an exhaustive compliance assessment, engineering certification or substitute for discipline studies.
The existing equipment list, summary and costing exports remain separate.

## Flow animation, loops, mirroring, parallel lines, single-line diagrams

- **Flow animation** – the viewer has an Animate flow toggle and speed slider; sidebar: Animate, Speed, Direction arrows, Direction. `auto` makes production flow towards the host and every other fluid away from it; per train use `"flow": "forward" | "reverse" | "none"`. The 2D animation uses CSS and fluid-dependent speed; exported SVGs animate in a browser. The 3D animation uses JavaScript pulses and the shared speed setting. PNG/print are static.
- **Loops that rejoin** – a branch with `"to": {"item": "<id>", "side": "up|down", "dx": 0, "label": "Rejoin"}` draws a return connector to any item of another train.
- **Right-to-left layouts** – `"mirror": true` on a train flips it (text stays readable, drag still works).
- **Parallel lines** – `pCount` (1–4) on a pipeline link draws N parallel lines; `sCount` / `uCount` do the same for service lines and umbilicals via props.
- **Electrical single-line diagrams** – eight `sld_*` symbols (breaker, disconnector, fuse, motor, generator, CT/VT, earthing, busbar); see the "Electrical single-line diagram" preset (mono theme).
